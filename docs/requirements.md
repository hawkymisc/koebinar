## 1. 文書目的・前提

本書は、ハッカソンで開発するAIウェビナーエージェント「Koebinar（コエビナー）」のMVP要件を定義する。開発チームの共通合意文書として利用する。

### 1.1 前提（ハッカソン制約）

- **AIの組み込みはOrcaRouter経由が必須**（ハッカソン規定）。全LLM呼び出しはOrcaRouterのOpenAI互換API（`https://api.orcarouter.ai/v1`）を通す。
- **外部プロバイダーのAPIキーはすべて運用者が持ち込む（BYOK）**。OrcaRouter・ElevenLabsの両方について、運用者が自分のアカウントのAPIキーを登録して利用する。利用料・クレジット・利用規約は各運用者のアカウントに帰属する。システム側の共有キーはデモ/開発用フォールバックとしてのみ保持する。
- MVPは自己完結型とする。外部ウェビナー基盤（Zoom等）連携、CRM連携は対象外。テナント分離は共有環境での最小データ境界として扱い、細粒度RBAC/SSOは対象外とする。
- 動画生成パイプラインは hawkymisc/daida-ai の設計（アウトライン→スライド→台本→TTS→合成）を流用しつつ、最終レンダリングは **Remotion** でMP4を出力する。
- 音声合成は日本語・英語とも **ElevenLabs（Eleven v3）のボイスクローン** に一本化する。1つのクローンVoiceで日英両言語のナレーションを生成する（GPUワーカー・言語別エンジンは持たない）。
- ElevenLabsについては、持ち込みアカウントのクレジット・クローンVoiceをそのまま利用する（詳細は上記BYOK前提に従う）。
- 開発期間は約1週間。技術スタックは「1週間で動くこと」を最優先に選定する。
- AIは登録されたナレッジのみを主な根拠とし、根拠不足時は回答保留または保留メッセージを返す。

> **MVPの一言定義**
> 「資料を渡すと、指定した声でしゃべるウェビナー動画（MP4）が出てきて、視聴者の質問にもその資料の根拠付きで答えるAIレイヤー」。

## 2. プロダクト概要

運用者がPDF・PPTX・テキスト資料を登録すると、LLM（OrcaRouter経由）がウェビナー構成案と各スライドのトークスクリプトを生成する。PDF/PPTXはブラウザ内でテキスト抽出し、サーバーへは抽出済みテキストだけを送る。スクリプトはElevenLabs（Eleven v3）のクローンVoiceでナレーション音声化され、Remotionでスライド映像と同期合成してMP4を出力する。生成された動画は組み込みプレイヤーで視聴でき、視聴者はその場で質問できる（RAG Q&A）。質問はIntent Signalとして構造化保存され、JSON/CSVで確認・エクスポートできる。

### 2.1 解決する課題

| **課題** | **現状** | **提供価値** |
|---|---|---|
| ウェビナー制作コスト | 台本作成・収録・編集に数日〜数週間 | 資料投入から数十分でナレーション付き動画 |
| 登壇者の確保 | 話者のスケジュール・撮り直しが制約 | クローン音声で「本人の声」のまま量産・修正可能 |
| 多言語展開 | 言語ごとに収録し直し | 台本翻訳＋同一クローンVoiceで「本人の声のまま」日英両版を生成 |
| 録画ウェビナーの低い対話性 | 見るだけで離脱しやすい | その場で質問できるRAG Q&A |
| 質問が営業データにならない | チャットログが未活用 | 質問を構造化しCSV/JSONで出力 |

## 3. ステークホルダーと利用者

| **ロール** | **主な目的** | **主要操作** |
|---|---|---|
| 運用者（管理者） | ウェビナー動画の制作・公開 | 資料登録、台本確認・修正、声の設定、動画生成、公開 |
| 視聴者 | 情報収集・疑問解消 | 視聴、質問、回答確認 |

※ v1.0にあった営業/SDR・モデレーター・テナント管理者の各ロールはPhase 2以降で再検討する。

## 4. スコープ

### 4.1 In Scope（ハッカソンMVP）

- PDF、PPTX、テキストのナレッジ取り込み・索引化（PDF/PPTXはブラウザ内で抽出）
- ウェビナー構成案（アウトライン）とスライド別トークスクリプトの生成（OrcaRouter経由）
- スライド画像/コンポーネントの生成（daida-ai由来のテンプレート思想: tech / casual / formal）
- プロバイダー接続設定（BYOK、integrations共通機構）
  - OrcaRouter: 運用者による自分のAPIキーの登録・検証・削除。検証は軽量なAPI呼び出し（モデル一覧取得等）で行う
  - ElevenLabs: 運用者による自分のAPIキーの登録・検証・削除。登録キーでのVoice一覧取得と使用Voiceの選択（持ち込みアカウントのクローンVoiceを利用可能）、プラン/クレジット残量の表示と利用条件の確認
- TTSナレーション生成（ElevenLabs Eleven v3、日英共通）
  - ボイスクローン（Instant Voice Clone）で登録した1つのVoiceを日英両言語で使用
  - 発音辞書による読み誤り補正（日本語の漢字読み対策）、文単位のリテイク
- Remotionによるスライド×音声同期レンダリング → MP4出力
- 生成物のプレビュー・修正・再生成（ステップ単位の再実行）
- 組み込みプレイヤーでの視聴とRAG Q&A（根拠付き回答、confidence、回答保留）
- 質問からのIntent Signal抽出（構造化JSON）と簡易ダッシュボード、CSV/JSONエクスポート
- ワークスペースID＋テナント固有トークンによるログイン、テナント別データ/BYOK分離、サイドバーナビゲーション

### 4.2 Out of Scope（MVP）

- 外部ウェビナー基盤（Zoom等）とのWebhook/Embed連携
- CRM（HubSpot/Salesforce）同期 → Phase 3
- テナント内の細粒度RBAC、ユーザー招待、SSO
- ライブ配信、リアルタイムAIアバター、音声Q&A
- メール配信/MA、決済
- 動画CDN配信の本格運用（MVPはローカル/オブジェクトストレージ直配信）

## 6. 機能要件

| **ID** | **機能** | **要件** | **優先度** |
|---|---|---|---|
| FR-001 | ナレッジ登録 | PDF/PPTX/Textを登録し索引化。PDF/PPTXはブラウザ側でテキスト抽出してから登録する（AR-01参照）。URL取り込みはMVPスコープ外（OD-10） | Must |
| FR-001a | 資料アップロードUI | Web UIから複数ファイルのドラッグ&ドロップ登録、登録済み資料の一覧・再利用ができる | Must |
| FR-002 | アウトライン生成 | テーマ・対象者・尺・**選択済み資料（document_ids、明示指定のみ）**・追加指示（FR-002a）からウェビナー構成案を生成 | Must |
| FR-002a | 追加指示（自由記述プロンプト） | ウェビナー作成時に自由記述の指示・重視点を入力でき、アウトライン生成・台本生成の両ステップに反映される | Should |
| FR-003 | スライド生成 | アウトラインからスライド（Remotion component/画像）を生成。テンプレート3種 | Must |
| FR-004 | 台本生成 | スライド別トークスクリプト生成。話法スタイル（casual/keynote/formal/humorous） | Must |
| FR-005 | 台本編集 | 生成台本の確認・手動修正・承認 | Must |
| FR-006 | TTS合成 | ElevenLabs（Eleven v3）で日英とも合成。日本語は文単位生成。使用キーは運用者の持ち込みキーを優先 | Must |
| FR-006a | プロバイダーキー登録 | 運用者がOrcaRouter / ElevenLabsのAPIキーをそれぞれ登録・差替え・削除できる。登録時に有効性を検証（EL: Voice一覧を必須、subscriptionはプラン・使用量表示用の任意照会、Orca: モデル一覧）。送信前にElevenLabsは`sk_`、OrcaRouterは`sk-`の接頭辞を検証し、不一致時はキーIDではなくAPIキー全文をコピーするよう案内して外部APIへ送信しない。成功したキーは暗号化して永続化し、画面遷移・APIプロセス再生成・非同期Workerでも同じテナントのキーを解決する。OrcaRouterのChat 401/403だけではキーを無効化せず、登録時と同じモデル一覧照会も認証失敗した場合だけ`invalid`へ変更する。入力欄付近で検証・生成に必要なAPIアクセス範囲と期限・IP・上限等の注意を確認できる。外部プロバイダーの401/403等はKoebinar認証失効と区別し、セッションを維持したままキー無効、権限・IP制限、レート制限、障害等の安全な原因別エラーを表示する。プロバイダーの構造化されたcode/messageはキー等を伏せ、長さを制限した上で原因判別用に表示する | Must |
| FR-006b | Voice選択 | ElevenLabs登録キーのアカウントからVoice一覧を取得し、動画生成に使うVoiceを選択できる | Must |
| FR-007 | 発音補正 | 発音辞書（TSV）適用と対象文のみのリテイク | Should |
| FR-008 | 動画レンダリング | Remotionでスライド×音声を同期合成しMP4出力 | Must |
| FR-009 | ステップ再実行 | 任意ステップ（台本修正後のTTSのみ再実行等）から再開 | Should |
| FR-010 | プレイヤー | 生成動画の再生と質問UI | Must |
| FR-011 | RAG検索 | 質問に関連するChunkを検索・ランキング | Should |
| FR-012 | AI回答生成 | 根拠付き回答・出典・confidence（OrcaRouter経由） | Should |
| FR-013 | 回答保留 | 低confidence・根拠なしは定型保留文 | Should |
| FR-014 | Intent抽出 | 課題、検討段階、時期等をJSONで構造化 | Could |
| FR-015 | ダッシュボード | 質問一覧・Signal集計・エクスポート | Could |
| FR-016 | 生成ログ | モデル、プロンプト版、生成物、コストを記録 | Should |
| FR-017 | テナント認証・分離 | ワークスペースログインを必須とし、資料・ウェビナー・ジョブ・質問分析・BYOK連携を認証テナントに分離する。別テナントIDの直接参照は404とする | Must |

## 7. AI・データ要件

| **ID** | **要件** | **初期基準** |
|---|---|---|
| AI-01 | 全LLM呼び出しをOrcaRouter経由とする | base_url統一。使用キーは運用者の持ち込みキーを優先。直接プロバイダー呼び出しはembeddings非対応時の例外のみ |
| AI-02 | 台本はKB内容を根拠とする | スライドごとに参照文書を保持 |
| AI-03 | Q&A回答は根拠不足時にfallback | citationなしでは回答を確定しない |
| AI-04 | 日本語品質 | 敬体、簡潔。TTS向けに読み誤りやすい語を発音辞書で管理 |
| AI-05 | TTS制約への適合 | 日本語は文単位で分割合成し、漢字読み誤りを発音辞書＋リテイクで補正。クレジット消費を見積り・キャッシュで管理 |
| AI-06 | 音声クローンの同意 | 参照音声・クローン元音声は本人同意を得たもののみ。Voice一覧取得では同意とみなさず、クローン/custom Voiceごとにテナントスコープの明示証跡を記録してから生成を許可する。同一テナント・同一provider Voice IDのキー差替えでは証跡を維持できる。同意取消は以後の生成を拒否し、ジョブ取消とは独立に扱う。各サービスの利用規約に従う |
| AI-07 | 構造化出力 | 台本・Q&A・IntentはJSON Schemaに適合 |
| AI-08 | 生成追跡 | 各生成物にmodel_id / prompt_versionを保存（OrcaRouterのログも併用） |
| AI-09 | ガードレール | PIIマスキング・プロンプトインジェクション対策はOrcaRouterのガードレール機能を第一層、アプリ側プロンプト設計を第二層とする |

### 7.1 Intent Signal（初期カテゴリ・簡易版）

v1.0の8分類（Problem/Technical Fit/Security/Pricing/Timeline/Competition/Decision Process/Negative）を踏襲するが、MVPではスコア計算・CRM連携は行わず、質問ごとの分類ラベル＋簡易集計のみとする。

## 8. 外部連携・技術スタック要件

| **区分** | **採用** | **連携方式** | **備考** |
|---|---|---|---|
| LLMゲートウェイ | **OrcaRouter**（必須） | OpenAI互換 REST | **運用者のAPIキー持ち込み（BYOK）**。アダプティブルーティング、ガードレール、コスト可観測性（各運用者のOrcaRouterダッシュボード）を利用 |
| 動画レンダリング | **Remotion** | Node.js / @remotion/renderer | React componentでスライド定義。daida-aiのパイプライン設計・テンプレート思想・発音辞書を流用 |

| ストレージ | ローカル or S3互換 | — | 資料原本、音声、動画 |

## 9. 非機能要件（ハッカソン水準）

| **ID** | **カテゴリ** | **要件** |
|---|---|---|
| NFR-01 | デモ成立性 | 資料投入→5分動画生成が審査時間内に完了する（事前生成キャッシュ併用可） |
| NFR-02 | 生成時間 | 5分尺動画の全パイプラインを目標30分以内（TTSバッチ・レンダリング含む） |
| NFR-03 | Q&A性能 | 質問→回答表示 p95 8秒以内（OrcaRouterルーティング込み） |
| NFR-04 | 再現性 | 同一入力・同一プロンプト版で再生成可能。中間生成物を保存 |
| NFR-05 | コスト | 1動画あたりの生成コストを把握（LLM: 各運用者のOrcaRouterダッシュボード＋アプリ側generation_logs、TTS: 文字数見積り） |
| NFR-06 | 可搬性 | TTS呼び出しをAdapter interfaceの背後に置き、将来のエンジン差替え（Irodori-TTS等）を妨げない |
| NFR-07 | 資料アップロードの安全性（AR-01） | PDF/PPTXのパースはブラウザ内（pdf.js / JSZip等の実績あるライブラリ）で完結させ、サーバーは抽出済みプレーンテキストのみを受け取る。悪意あるファイルの影響範囲をアップロード者自身のブラウザタブに限定し、サーバー側の任意コード実行・他ウェビナーへの波及を避ける。ファイルサイズ・展開後サイズの上限チェックを行う |

## 10. セキュリティ・コンプライアンス（MVP最小セット）

- システム保有のデモ用フォールバックキー（OrcaRouter / ElevenLabs）は環境変数または.env管理とし、リポジトリにコミットしない。
- **持ち込みキー（OrcaRouter / ElevenLabs）はいずれも暗号化してDB保存**し、平文では保存・ログ出力しない。UI/APIレスポンスには末尾4桁等のマスク表示のみ返し、キー全文をフロントエンドへ返さない。外部API呼び出しは必ずサーバー側で行う。
- 運用者トークンからサーバー側で `tenant_id` を一意に決定し、クライアント指定のテナントIDを認可根拠にしない。別テナントのリソースIDを指定した場合は404を返す。
- 持ち込みキーの登録時に、権限を絞った専用キーの発行を推奨する案内を表示する（EL: TTS＋Voices読み取りスコープ＋クレジット上限。Orca: 利用可能な範囲でのキー分離・上限設定）。
- PII・機微情報を含む資料はデモに使用しない。プロンプトへのPII混入はOrcaRouterのPII Shieldで抑止する。
- 音声クローンは本人同意のある音声のみ。クローン/custom Voiceは同意主体・時刻・確認文バージョンを記録し、取消可能にする。生成動画には「AI生成ナレーション」である旨を表記する（なりすまし・誤認防止）。
- KB文書内の命令文はデータとして扱い、System命令を上書きさせない（アプリ側プロンプト設計＋OrcaRouterのPrompt Injectionガードの二層）。

## 11. KPI・受入基準（ハッカソン審査観点）

| **区分** | **KPI/基準** | **判定** |
|---|---|---|
| 完成度 | 資料→MP4のE2Eデモ完遂 | 審査デモで1本通し |
| 品質 | 台本のGrounded率 | サンプル20問の評価セットで確認 |
| 音声 | JA/EN両言語のナレーション生成 | 各1本以上 |
| 必須要件 | OrcaRouter経由のAI呼び出し | 全LLM呼び出しがOrcaRouterログに記録 |
| 対話性 | Q&Aの根拠付き回答 | 出典表示・保留動作の確認 |

### 11.1 MVP受入条件

1. テスト資料を登録し、アウトライン・台本・スライド・音声・MP4が生成される。
2. 台本を修正して該当ステップから再生成できる。
3. 同一クローンVoiceによる日本語動画と英語動画が各1本生成される。
4. 全LLM呼び出しがOrcaRouter経由であることをログで確認できる。
5. 運用者が自分のOrcaRouterキーとElevenLabsキーを登録し、自分のアカウントで台本生成・音声生成が行われる（いずれかのキー削除後は該当機能が生成不可になる）。
6. クローン/custom Voiceは明示的な同意証跡がなければウェビナー作成・ジョブ実行・TTS呼び出しで拒否され、同意取消後も生成されない。
7. 根拠不足の質問で保留メッセージが返る。
8. 2つのワークスペースで資料・ウェビナー・ジョブ・BYOK連携が相互に一覧表示・直接参照されない。

達成状況は本項の記述だけで判断せず、`docs/audit_report.md` の実装・テスト証拠と未解消項目を参照する。

## 12. リスク・制約

| **リスク** | **影響** | **対策** |
|---|---|---|
| ElevenLabsの日本語読み誤り | ナレーション品質低下 | Eleven v3モデル指定、文単位分割、発音辞書、対象文のみのリテイク |
| ElevenLabsクレジット/コスト | 音声生成の制限 | 文字数見積り、生成キャッシュ、デモ分の事前生成。BYOKでは登録時にsubscription照会し残量を表示 |
| 持ち込みキーの不備 | 接続または生成失敗（provider側403/401等） | 登録時検証（有効性・必要スコープ・プラン）。登録時のproviderエラーはKoebinar APIの422へ正規化してログイン状態を維持し、利用API・期限・IP・上限等の確認を案内 |
| 持ち込みキーの漏えい | 運用者アカウントの不正利用 | 暗号化保存、マスク表示、ログ非出力、制限付きキー（スコープ・クレジット上限・有効期限）の発行を推奨 |
| ElevenLabs障害・単一依存 | 音声生成の全停止 | 生成済み音声のキャッシュ再利用。デモ保険としてedge-tts等へのフォールバックフラグを保持 |
| Remotionレンダリング時間 | デモに間に合わない | 解像度/尺の調整、事前レンダリング、並列化 |
| LLM台本のハルシネーション | 誤情報の動画化 | KB根拠必須、台本の人間承認ステップ（FR-005） |
| 音声クローンの悪用懸念 | 規約違反・信用毀損 | 同意音声のみ、AI生成表記、審査での明示 |
| OrcaRouter障害/レート制限 | 生成停止 | 自動フェイルオーバー機能に依存しつつ、リトライとキャッシュ |
| 持ち込みOrcaRouterキーの残高不足 | 台本・Q&A生成の停止 | 登録時検証＋生成失敗時に残高確認を案内。デモはフォールバックキーで継続可能 |
| 悪意あるPDF/PPTXによるパーサ脆弱性攻撃 | サーバー乗っ取り・他ウェビナーへの波及 | 抽出をブラウザ内（pdf.js/JSZip）に限定しサーバーはプレーンテキストのみ受領（NFR-07/AR-01）。ファイルサイズ・展開後サイズの上限チェック |
